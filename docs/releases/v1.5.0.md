# v1.5.0 — local mode: every check on your PC with the KiCad you have

## What's new since v1.4.0

**Local mode** (roadmap phase 7B)
- `python scripts/kicad_hub.py run`, from a board repository, does on a PC what the action does on GitHub: ERC/DRC (and the DRC with a fab's rules), per-part BOMs compared with `main`, datasheets, prices, the fab package, requirements, the report and the design portal page
- It uses the KiCad installed on the PC and its own Python: nothing to install, no Docker. `kicad-cli` is found by itself
- The working tree is what gets checked, so changes can be reviewed before committing
- The portal opens from a local web server (the command prints how); supplier keys can live in a personal file outside the repository
- Tried on Windows with KiCad 10.0.5: same results as CI on the example board

**One engine for the action and the PC**
- The action's steps (ERC/DRC, BOM, datasheets, prices, fab package, requirements, report, portal page) now call `scripts/kicad_hub.py` instead of long bash scripts. The results in CI are the same as before
- Checksums and the fab zip are made in Python, so they no longer need `sha256sum`, `zip` or `jq`
- The requirements file is readable without PyYAML

**Fixes**
- The fab DRC table groups violations by type and rule name, so it works with KiCad in any language (a Spanish KiCad wrote "regla" where the report looked for "rule")
- The fab notes step can no longer hang on Windows: a "font not found" message no longer opens a window that waits for OK, and the step stops itself after 300 s in any case
- Reports, BOMs and packages of an earlier run are removed first, so a run never shows another run's results
- A `kicad-cli` that writes no output is now an error that names the missing file, instead of a later step failing
- Python bytecode is no longer tracked in the repository

Users pinned to `@v1` get this automatically.
