## Repository layout

```
.
├── <board>.kicad_pro      KiCad project
├── <board>.kicad_sch      root schematic (+ one file per hierarchical sheet)
├── <board>.kicad_pcb      PCB
├── sym-lib-table          project symbol libraries (paths use ${KIPRJMOD})
├── fp-lib-table           project footprint libraries (paths use ${KIPRJMOD})
├── lib/
│   ├── project.kicad_sym  board-specific symbols
│   ├── project.pretty/    board-specific footprints
│   └── 3d/                3D models (stored with Git LFS)
├── docs/                  datasheets notes, calculations, images
└── .github/               PR template and CI workflow
```

Fabrication outputs (`fab/`) are generated by CI and are never committed.

## Working rules

- **One owner per file.** KiCad files don't merge well: split the schematic in
  hierarchical sheets, one person per sheet, and a single PCB owner at a time.
- **Small pull requests**, reviewed with the checklist in the PR template.
- **Project libraries only through `${KIPRJMOD}`**, so the project opens on any
  machine without extra setup.
- **3D models in `lib/3d/`** and referenced as `${KIPRJMOD}/lib/3d/<model>.step`.

## Getting started

```
git lfs install          # once per machine
git clone <repo-url>
```

Open `<board>.kicad_pro` in KiCad.

## CI

`.github/workflows/kicad.yml` runs [kicad-hub](https://github.com/JMcordobamendez/kicad-hub)
on every push and pull request: ERC/DRC, BOM checks and diff, prices and stock,
before/after images in the PR comment and the fab package (artifact
`<board>-fab`). Tag `vX.Y` to publish the fab package as a release.

- Set `project-dir` in the workflow if the `.kicad_pro` isn't at the repo root.
- Prices come from LCSC and JLCPCB out of the box. For Mouser, Farnell and DigiKey,
  add your own API keys as repository secrets (`MOUSER_API_KEY`,
  `FARNELL_API_KEY`, `DIGIKEY_CLIENT_ID`, `DIGIKEY_CLIENT_SECRET`):
  [how to get them](https://github.com/JMcordobamendez/kicad-hub#supplier-api-keys).
- Supplier picked per part: open `sourcing.html` from the artifact, choose, and
  commit the downloaded `kicad-hub-sourcing.csv` next to the `.kicad_pro`.
- Requirements: `kicad-hub-requirements.yaml` lists what the board must meet (cost,
  layers, size, stock...); CI checks it and shows a pass/fail table. Uncomment the
  ones you need.
- Design portal (schematic and PCB in the browser, iBOM, downloads): after the
  first run, *Settings → Pages → Deploy from a branch → `kicad-hub-site` / (root)*.
  Pages is free for public repositories.
- `.github/workflows/kicad-hub-cleanup.yml` removes a PR's images and portal page
  when the PR is closed.
